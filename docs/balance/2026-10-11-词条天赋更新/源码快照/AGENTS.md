# 项目协作约定

## 难度测试的默认口径

用户在2026-10-11明确纠正了测试口径。以后要求“模拟当前版本难度曲线”“按低、中、高玩家测试”“照上次做数值测试”时，默认执行正常游玩模拟，不需要重新询问是否预置阵容。

- 低阶：novice策略，无局外成长；中阶：ordinary策略，半局外成长；高阶：expert策略，满局外成长、解锁池全部开放。
- 所有档位从第一关和空阵容开始。奖金、免费招募、天赋候选按正式核心发放；球员、装备、球衣、星级、训练和事件奖励必须正常获取。高阶满配是成型目标，不是开局赠送。
- 按真实招募、经济、购物、训练、羁绊、事件、战斗、死亡流程测试，不偷看未交手对手的隐藏策略和未公开的词条抽取，不替换随机结果。低、中阶广告关闭；高阶积极观看所有可获得收益的广告（天赋自选、S级招募、词条5星自选、一次死亡恢复），模拟广告完整观看成功，并遵守真实次数与资格限制。新旧对比采用相同广告策略，旧无广告参考保留。
- 默认每档至少100局、相同种子组。更新前后使用同一组种子、相同策略与测试边界，各跑低、中、高100局进行对比。运行至死亡；任何操作、时间、关卡边界导致的截断单独统计，不当作死亡。存在截断时不得宣称测得最终止步上限。
- 每局每关取第一次开战前面板OVR；图中两线为实际到达玩家OVR中位数与对手OVR。显示到达人数／比例和玩家范围；玩家死亡后不补点，无人到达处不外推。
- 更新时保留上个版本的难度曲线静态页面和原始数据；新版与对比页面另存目录，并提供旧页面链接，不覆盖旧HTML。
- 报告区分已通过关卡和最后挑战关卡，区分样本最高值与理论上限；说明后期幸存者偏差与AI策略局限。
- 保存原始种子、配置、源码哈希、逐关轨迹、结局、JSON/CSV和可本地查看的HTML，至少核对每档一局浏览器核心与云端权威回放，并运行相关验证。
- 正常测试入口：`npm run balance:reference -- --count 100 --out docs/balance/YYYY-MM-DD-更新/正常游玩.json`；验证：`npm run balance:reference:test`。更新版本时设置 `BALANCE_NATURAL_SNAPSHOT` 指向新快照，不用修改旧快照来消除差异。新旧数值对比入口：`npm run balance:compare`。
- 满配压力上界只能单独作为辅助测试，入口`balance:reference:pressure`，不得替代自然成长主图。第一关673 OVR及474关交点来自旧预置压力模型，不能作为真实游玩结论。

## 文档维护

2026-10-11用户已明确要求测试“新增词条系统＋修改开局天赋”更新，撤销此前暂缓要求，并将样本扩为低、中、高各100局。更新前后都跑100局，用同种子对照；已有30局旧参考继续保留。

文档入口是[项目说明](项目说明.md)和[文档导航](docs/文档导航.md)。新的人类阅读文档使用中文文件名，按玩法、数据、运维分类；修改规则后更新当前说明，清理被取代的草案，不积累重复版本总结。

`docs/balance/2026-10-11/`是用户要求保留的数值参考，文件内容和名字均不要改。新版本另建目录。`AGENTS.md`是工具约定名；`BALANCE_REPORT.md`是该受保护目录引用的兼容入口，保留名称。第三方技能目录、源码、SQL迁移、部署文件不属于一般文档清理范围，不因文件名英文而删除或改名。

用户的“记住”通过此项目约定持久保存；新的会话先阅读此文件和当前文档导航。不能承诺脱离这个仓库的任何会话都自动拥有本次对话历史。
