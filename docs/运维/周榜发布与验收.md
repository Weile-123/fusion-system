## 实现与存储

- `activity/cloudfunctions/activity_api/index.js`：只有 OVR 的 `scope=weekly` 请求调用新 RPC；原请求保持原结构，传奇点榜不变。`weeklyLeaderboardVersion=1` 只表示代码支持，不代表数据库已启用。
- `20261010190000_weekly_ovr_leaderboard.sql`：两套迁移目录内容一致，在一个事务中增加周榜结构和触发器，不替换累计榜及旧计分 RPC。
- `weekly_ovr_settings.enabled_at`：默认 NULL，周榜关闭。启用之前的对局不补录。未来时间可以安排一次性上线，之后无需人工切周。
- `leaderboard_runs.weekly_ovr_start`：新对局由服务端时间确定所属周，客户端不能指定。规则版本 1～6 的已验证对局都走相同插入触发器；未验证旧局不计入周榜。
- `weekly_ovr_entries`：每人每周最高分，保留实际战斗关卡、来源对局和战斗序号。同分不替换首次达到时间。
- `weekly_ovr_periods` / `weekly_ovr_snapshots`：周期结束后，以分数降序、达到时间升序、用户标识稳定排序冻结前 50。昵称随快照保存，不跟随玩家后续改名。
- 战斗插入与周分数更新在同一数据库事务内。周写入失败则原战斗、累计榜及验证进度也回滚，客户端可安全重试；成功响应不会漏掉周写入。
- 归档和写入锁定同一周期行。取得锁之后用数据库真实时钟检查截止时间；不使用事务开始时的 now()。过期后即使尚未生成快照，也不接受后续成绩。
- 当前周由 `Asia/Shanghai` 周一零点决定，周期长度固定 168 小时，不受服务器时区或夏令时影响。查询补做缺失归档，无需定时任务准点触发；长期无人访问后也可恢复历史快照。
- 上周个人排名只查询自己的快照记录，不在前 50 返回空 entry。查询可固定列表 weekId，避免零点时列表和个人排名混周。仅允许当前/最近两周范围的合法周一 ID。
- 累计 OVR 和总传奇点始终保留。跨周继续旧局照常保存战斗和发放传奇点，但不更新已结束的周榜，也不进入新周榜。
