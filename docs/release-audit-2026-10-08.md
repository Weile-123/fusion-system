## 已修复的问题

| 问题 | 修复位置与处理 |
| --- | --- |
| 平台存档写入卡住，会延迟后续设备存档 | `h5/storage-adapter.js`、`h5/game-ui.js`：设备写入立即执行，平台写入单独串行；双端失败保留错误提示 |
| 平台空响应或错误响应可能覆盖设备存档 | 存储适配器检查响应状态和存档版本，再比较时间戳 |
| 恢复存档允许超过当阶段上限的升星、训练 | 恢复时按实际球员、天赋及阶段规则限制；保留合法无尽成长 |
| 云端旧的升星、训练硬上限会拒绝合法无尽阵容 | 云函数使用共享核心规则校验，并检查阵容重复、替补容量、装备槽、加成范围、种子和天赋 |
| 战斗同步失败丢失云端局标识，无法继续正常入榜 | 保留待提交战斗快照，持久化到存档；继续、结算和新开局前重试；请求去重 |
| 已结算后复活，云端仍认为该局结束 | 增加恢复接口及数据库事务，撤回原结算积分后重新结算，保留一次分享奖励 |
| 分享奖励未计入云端总传奇点 | 新增按用户与局标识绑定的分享奖励接口，每局最多计入 100 点 |
| 网络重试可能重复计战斗、奖励 | 新增战斗事件表和幂等事务；恢复、分享接口均可重试 |
| 复活广告成功后未刷新任务状态 | 增加任务刷新；所有广告只在成功且 `rewarded === true` 时发奖，等待期间阻止重复操作 |
| 开局云请求期间重复点击 | 确认按钮禁用并展示加载图标，阻止重复开局及改选天赋 |
| 个别负收益组合可产生负奖金 | 战斗收益最低为 0，前后端共享核心一致 |
| 发帖缺少版块配置能力时仍尝试调用 | 先检查并等待 `bbsConfig.get()`，空配置不传整套版块字段 |
| 海报上传返回不可信图片地址 | 接受 HTTPS 且精确匹配虎扑技能允许的图片域名后才打开发帖编辑器 |
| 畸形身份上下文、请求体导致异常 | 限制解压及请求体大小，正确拼接 UTF-8 字节，拒绝非法 JSON 类型，身份解析失败按未授权处理 |
| 发布包改写 URL 和 DOM 关键字 | 移除构建阶段字符编码改写，保留正常可审查产物 |
| 云函数包依赖整个项目本地目录 | 删除未使用的 `file:../../..` 依赖并更新锁文件 |

## 虎扑接口核对

依据项目内 `hupu-ai-game-skills` 的实际契约核对实现；下表中的原生调用均通过模拟 SDK 验证，不能替代真机回调测试。

| 接口 | 核对结果 |
| --- | --- |
| `auth.getUserInfo` | 检查成功码与登录状态，用户名有“玩家”兜底；云端身份来自受保护网关上下文，不接受前端自报用户 ID |
| `storage.getValue` | 技能示例使用键名字符串；当前调用方式有依据，并非必须传 `{key}`。返回包需解析为实际存档 |
| `storage.setValue` | 传普通键值对象，设备与平台各自保存；平台写入按顺序执行。真机仍需测重启后读回及存档大小限制 |
| `vatask.completeRewardVideo` | 必须用户点击触发；仅成功码加 `rewarded === true` 发奖；取消不发奖，等待中按钮禁用 |
| `vatask.getActivityTaskState` | 广告成功后刷新，包含复活路径 |
| `cloud.request` | 写操作与个人排名使用认证和环境 ID；公开榜单最多 50 名；处理网关状态码及业务码；战力榜使用单局 OVR |
| `oss.uploadFile` | 使用生成海报 Blob；检查上传结果和图片地址后传入编辑器 |
| `bbsConfig.get` | 等待配置返回；仅有效配置才传完整版块配置字段 |
| `request.bbsOpenPostEditor` | 成功回调只证明编辑器已打开。按照此前产品约定在该回调发放一次奖励，页面仍显示“首次分享”及“已获得奖励·100传奇点” |

使用的技能：`colorbox-auth-get-user-info`、`colorbox-storage-get-value`、`colorbox-storage-set-value`、`colorbox-vatask-complete-reward-video`、`colorbox-vatask-get-activity-task-state`、`colorbox-cloud-request`、`colorbox-oss-upload-file`、`colorbox-request-bbs-open-post-editor`、`colorbox-result-poster-posting`、`colorbox-leaderboard-template`、`act-cloudbase`、`colorbox-audit-hupu-web-security`；另查阅 `colorbox-security-check-audit` 的文本审核契约，本次没有新增文本审核调用。

技能工作流的 Python 状态工具因本机 Python 别名不可执行而未运行成功；没有据此宣称完成正式审核或发布审批。

## 尚未解决：榜单防作弊

风险级别：高，影响公开竞争榜单的可信度。

`activity/cloudfunctions/activity_api/index.js` 的 `validateRun()` 验证范围和合法组合，战斗接口再从数据库核对本局种子及天赋，并运行共享 `C.battle()` 计算胜负与 OVR。但阵容、训练、升星、装备、加成和当前随机数状态仍由客户端提交，云端没有验证其逐步获得过程。

因此，经过修改的客户端仍可能提交表面合法但实际未获得的强阵容，或者改动随机数状态。此次校验加固和幂等修复没有关闭这个漏洞。完整处理需要服务端保存并验证招募、购买、训练等操作及随机数演进，或实现可验证的操作回放。复活广告和编辑器回调也没有服务器独立凭据验证，不应视为服务端已证明观看或发布完成。
